# MnesOS Implementation Plan – 2026-05-21

This plan outlines the implementation strategy for preserving Director thought processes and planning context across asynchronous minigame boundaries. Tasks are structured as JIRA-style cards to enable clear tracking.

### [MnesOS-260521-01] Engine – Memento-Based Director Thought Preservation
- **Status:** **Backlog**
- **Objective:** Rehydrate and restore the Director LLM's thought process across the asynchronous minigame boundary without using stateful checkpointers, preserving narrative continuity by continuing the previous Scene Directive.
- **Description:** 
    - Update `src/MnesOS/graph/nodes/minigame_output.py` to save the newly generated pre-game `Scene Directive` block directly to a transient state key: `state["bot_memory"]["_previous_scene_directives"]`.
    - Verify that this transient state update is captured in the turn's `yare_delta` and persisted in the database `TurnLog` by the API route.
    - Update `src/MnesOS/graph/nodes/director.py` to check for `_previous_scene_directives` on the resolution turn and inject it as a structured reference prefix.
    - Explicitly instruct the Director LLM that the pre-game setup has already been narrated to the player, and it must generate only the *new* resolving Scene Directives (part-2) for the post-game physical outcomes, avoiding redundancy.
    - Implement a cleanup step at the end of the graph execution (e.g., inside the Narrator node or a post-resolution cleanup helper) to pop `_previous_scene_directives` from `bot_memory` once the turn is resolved.

### [MnesOS-260521-03] Frontend – Fix Stringly-Typed `_pending_interaction` Parsing
- **Status:** **Backlog**
- **Priority:** **High**
- **References:** `docs/design/web-client.md §7.2`
- **Objective:** Eliminate the fragile Python-repr-to-JSON coercion in `useGameSession` that silently drops the mini-game flow whenever `_pending_interaction` contains apostrophes or nested quotes.
- **Root Cause:** The backend writes `_pending_interaction` as a Python `repr()` string. The client works around this with `pending.replace(/'/g, '"')`, which corrupts any string value containing a single-quote and raises a silent `JSON.parse` failure.
- **Description:**
    - **Backend fix (root cause):** Audit all graph nodes that write to `state["bot_memory"]["_pending_interaction"]` (in `src/MnesOS/graph/nodes/`) and ensure the value is always a native Python `dict`, not a string. Confirm the `yare_delta` serialization writes it as a JSON object to the `TurnLog`.
    - **Client fix:** In `web-client/src/hooks/useGameSession.ts`, inside `applyBotMemory`, remove the `string` branch that calls `pending.replace(/'/g, '"')`. Retain only the `object` branch. Add a `console.warn` if `pending` is a non-object type to surface future regressions early.
    - **Validation:** Add a unit test covering a turn whose `bot_memory` contains a `_pending_interaction` dict with a string value that includes an apostrophe (e.g., `"It's a trap"`). Verify it parses correctly without corruption.
    - After fixing this issue, modify `docs/design/web-client.md` to strike through the anti-pattern entry in §7.2 and add a `(Fixed in MNS-260521-03)` note.

### [MnesOS-260521-04] Frontend – Decompose God Component `App.tsx`
- **Status:** **Done**
- **Priority:** **High**
- **References:** `docs/design/web-client.md §6.1, §7.1`
- **Objective:** Split `App.tsx` (7 responsibilities, 8 `useState` hooks, 2 `useEffect` hooks) into independently testable, single-purpose units.
- **Description:**
    - **Extract `AuthProvider` context** (`web-client/src/contexts/AuthContext.tsx`): owns `authLoading`, `authError`, the PKCE `useEffect` callback, and `setOpenRouterKey`. Expose a `useAuth()` hook. `App.tsx` wraps the tree in `<AuthProvider>`.
    - **Extract `GameInstanceContext`** (`web-client/src/contexts/GameInstanceContext.tsx`): owns `activeInstanceId` and `minigameOpen`. Expose a `useGameInstance()` hook, consumed by `PlayHub`, `ChatPane`, and `MinigameWrapper`.
    - **Extract `<AppShell>`** (`web-client/src/components/AppShell.tsx`): owns the header, navigation `view` state, `settingsOpen`, `startNewGameOpen`, and conditional view rendering. `App.tsx` becomes a thin composition root: `<AuthProvider><GameInstanceContext><AppShell /></GameInstanceContext></AuthProvider>`.
    - Auth overlay and error banner rendering moves into `AuthProvider` or `AppShell`, leaving zero UI logic in `App.tsx` itself.
    - After fixing this issue, modify `docs/design/web-client.md` to strike through the anti-pattern entries in §6.1 and §7.1 and add a `(Fixed in MNS-260521-04)` note.

### [MnesOS-260521-05] Frontend – Replace `window` Custom Event Bus with Explicit Callbacks
- **Status:** **Done**
- **Priority:** **High**
- **References:** `docs/design/web-client.md §7.4`
- **Objective:** Remove the implicit `window.dispatchEvent("mnesos-play-instance")` navigation bus across three components and replace it with explicit React callbacks, making navigation state traceable and type-safe.
- **Affected dispatch sites:** `PlayHub.tsx` (`handleResume`), `GameInstanceManager.tsx` (identical resume path), `App.tsx` (`StartNewGameModal`'s `onStart` callback).
- **Description:**
    - Define `PlayInstancePayload = { instance_id: string; turn_id: string | null }` in `web-client/src/types/index.ts`.
    - Replace the `window.addEventListener("mnesos-play-instance", ...)` listener in `App.tsx` with a plain `onPlayInstance(payload: PlayInstancePayload) => void` callback (or a context setter if MNS-260521-04 is implemented first).
    - Pass `onPlayInstance` as an explicit prop to `PlayHub`, `GameInstanceManager`, and `StartNewGameModal`. Each calls the callback directly instead of dispatching a `CustomEvent`.
    - Remove all `window.dispatchEvent(new CustomEvent("mnesos-play-instance", ...))` calls and the corresponding `addEventListener` / `removeEventListener` calls from `App.tsx`.
    - **Dependency:** If MNS-260521-04 is completed first, `onPlayInstance` becomes the `GameInstanceContext` setter rather than a drilled prop.
    - After fixing this issue, modify `docs/design/web-client.md` to strike through the anti-pattern entry in §7.4 and add a `(Fixed in MNS-260521-05)` note.

### [MnesOS-260521-06] Frontend – Fix Stale Closure in `mnesos-play-instance` useEffect
- **Status:** **Done**
- **Priority:** **Medium**
- **References:** `docs/design/web-client.md §7.6`
- **Objective:** Prevent the navigation event listener from being torn down and re-registered on every render cycle, closing the window where events fired during rapid state transitions are silently dropped.
- **Root Cause:** `App.tsx` lines 62–73: the `useEffect` dependency array is `[session]`. The `session` object from `useGameSession` is a new reference on every render, causing continuous listener churn.
- **Description:**
        - This card has been marked Done because it was obsoleted by MNS-260521-05 (the global `window` event bus was removed and replaced with explicit callbacks). No further action is required. If the event-bus reappears, re-open this ticket and implement the stable `useCallback` change described below.
        - If ever needed, the intended fix would be:
            - In `web-client/src/hooks/useGameSession.ts`, wrap `resetSession` in `useCallback` with a stable dependency array (only the stable setter identities it depends on: `setMessages`, `setCurrentTurnId`, etc.).
            - In `web-client/src/App.tsx`, change the `useEffect` dependency array from `[session]` to `[session.resetSession]` so the listener is only re-registered when the function identity actually changes.

### [MnesOS-260521-07] Frontend – Enforce Type Safety at the Mini-Game Boundary
- **Status:** **Backlog**
- **Priority:** **Medium**
- **References:** `docs/design/web-client.md §6.4, §7.3`
- **Objective:** Replace `pendingInteraction?: any` on `ChatPane` with a strict type, and split the monolithic 16-member `GameSession` interface to remove unnecessary coupling on display-only consumers.
- **Description:**
    - **Fix `ChatPane` prop type:** In `web-client/src/components/ChatPane.tsx`, replace `pendingInteraction?: any` with `pendingInteraction?: PendingInteraction | null`. Move the `PendingInteraction` interface (currently private to `MinigameWrapper.tsx`) into `web-client/src/types/minigames.ts` and export it so both `ChatPane` and `MinigameWrapper` import from the shared types file.
    - **Split `GameSession`:** In `web-client/src/hooks/useGameSession.ts`, split the interface into:
        - `GameSessionState` — the 7 read-only data fields (`messages`, `botMemory`, `pendingInteraction`, `currentTurnId`, `loading`, `error`, `saves`).
        - `GameSessionActions` — the 9 mutating methods (`sendTurn`, `sendInteraction`, `retryLast`, `saveCheckpoint`, `loadCheckpoint`, `refreshSaves`, `clearError`, `clearSession`, `resetSession`).
        - Export `GameSession = GameSessionState & GameSessionActions` to preserve backward compatibility for `App.tsx`.
    - Update display-only consumers (`ChatPane`, `StateDebugger`, `SaveManager`) to accept `GameSessionState` (or individual fields) rather than the full `GameSession`, preventing them from accidentally invoking mutating methods.
    - After fixing this issue, modify `docs/design/web-client.md` to strike through the anti-pattern entries in §6.4 and §7.3 and add a `(Fixed in MNS-260521-07)` note.

- **Description:**

    - Ensure the final event in the stream contains the full `TurnResponse` (turn_id, narrator_response, yare_delta) consistent with existing state-mutation and persistence expectations.

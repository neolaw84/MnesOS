# MnesOS Alpha-1.5 JIRA Backlog Cards – 2026-05-25

This document defines the new JIRA cards added to the backlog for the MnesOS Alpha-1.5 development phase.

---

### [MnesOS-260525-01] Frontend – YARE JS Developer Playpen/Testing Pane
- **Status:** **Backlog**
- **Priority:** **High**
- **Objective:** Build a sub-page/sub-pane in the developer UI that allows developers to write and run Javascript YARE specs locally using `eval`.
- **Description:**
    - Create a sub-pane/sub-page in the cartridge builder UI.
    - Implement a playground text editor where the developer can write custom JavaScript YARE rules.
    - Allow mocking a game state (JSON object) and run JS-based rules against it using `eval` for quick iteration.
    - Provide immediate console-style feedback showing execution logs, returned values, and mutations to the mock state.

### [MnesOS-260525-02] Frontend – Builder UI 4-Pane Enhancements: Format Switching & Syntax Highlighting
- **Status:** **Backlog**
- **Priority:** **High**
- **References:** `[MnesOS-260507-08]`
- **Objective:** Enhance the 4-pane builder split-screen to support format switching (YAML vs JS) on the YARE pane and integrate syntax highlighting.
- **Description:**
    - Modify the split-pane builder layout to feature four distinct panes: First Message (`.md`), Prompt Directive (`.yaml`), YARE Rules (`yare.yaml`/`yare.js` switchable), and Bot Lore (`.md`).
    - Add a switch toggle in the YARE Rules pane to toggle between writing in JavaScript or YAML, modifying the local draft structure.
    - Integrate a lightweight editor (e.g. Monaco Editor, react-simple-code-editor) to provide syntax highlighting for Markdown, YAML, and JavaScript.

### [MnesOS-260525-03] Frontend – Individual Pane File Export
- **Status:** **Backlog**
- **Priority:** **Medium**
- **References:** `[MnesOS-260507-11]`
- **Objective:** Allow developers to download the contents of individual panes as separate files in the browser.
- **Description:**
    - Add a "Download/Export File" button to the header of each of the 4 builder panes.
    - Ensure the download maps to the correct file extension and standard naming conventions: `first_message.md`, `prompt_directives.yaml`, `yare.js` / `yare.yaml`, and `bot_lore.md`.
    - Implement clean browser-side file downloads using blob generation.

### [MnesOS-260525-04] Frontend/Backend – Cartridge Version Saving UI and Endpoint
- **Status:** **Backlog**
- **Priority:** **High**
- **References:** `[MnesOS-260510-11]`, `[MnesOS-260507-11]`
- **Objective:** Enable saving new cartridge versions directly from the developer GUI, in addition to file/ZIP upload.
- **Description:**
    - Build a UI control in the cartridge builder (e.g. "Save Version") that lets the developer input a version name/number.
    - Implement a backend API endpoint (e.g., `POST /api/cartridges/{id}/versions`) that receives the raw JSON contents of the 4 active panes.
    - Run backend validations (syntax, security) on the draft, bundle it as a cartridge version, and commit it to the database cartridge catalog.
    - **Co-existence:** Ensure this new direct saving functionality operates side-by-side with the existing file-by-file and ZIP upload workflows without modifying, deprecating, or breaking their current UI interfaces.

### [MnesOS-260525-05] Backend – Integrate JS-to-YAML Compilation into Ingestion Pipeline
- **Status:** **Backlog**
- **Priority:** **High**
- **References:** `[MnesOS-260516-12]`
- **Objective:** Translate uploaded or saved JS-based YARE cartridge rules into standard YAML representations during ingestion using the static AST compiler.
- **Description:**
    - Update the backend cartridge ingestion and validation logic to check if a cartridge defines its rules using JavaScript (`yare.js`).
    - Run the Python-based static AST compiler on the `yare.js` source to generate the standard `yare.yaml` representation during save or upload.
    - Reject any cartridge saves/uploads immediately if the static compiler raises validation errors for unsupported or unmappable JS syntax.
    - Store both the original `yare.js` source and the compiled `yare.yaml` in the cartridge database record.

### [MnesOS-260525-06] Engine/Frontend – Minigame Registry Discovery and Parameter Directory
- **Status:** **Backlog**
- **Priority:** **Medium**
- **References:** `docs/design/mini-games.md`
- **Objective:** Expose the available minigames and their difficulty/output parameters in the developer GUI.
- **Description:**
    - Implement a backend API endpoint `/api/minigames` that parses the frontend's compiled `/schemas/minigames.json` or local minigame registry.
    - Return a list of all registered mini-games along with their required difficulty parameters, expected assets, and returned metrics.
    - Design and build a directory panel in the developer GUI showing this information, making it easy for developers to copy-paste valid YARE triggers and parameters.

### [MnesOS-260525-07] Database/Backend – Schema Update for JavaScript YARE (Drafts & CartridgeVersions)
- **Status:** **Backlog**
- **Priority:** **Medium**
- **References:** `[MnesOS-260507-11]`
- **Objective:** Update the database drafts and cartridge version tables to support and persist raw JS-based YARE source code alongside compiled specifications.
- **Description:**
    - Apply database schema migrations to the `cartridge_drafts` table to store the active rule file type (`yare_type` as 'yaml' or 'js') and the code contents.
    - Apply database schema migrations to the `CartridgeVersion` table (and update the Python `CartridgeVersion` data class) to add a new nullable column `yare_js_src` for storing the plain-text JavaScript YARE source.
    - Update SQLite/PostgreSQL store implementations, the `CartridgeLoader.load_from_version` function, and API routes to save, fetch, and serialize `yare_js_src`.
    - Update the REST API auto-save and draft retrieval endpoints to serialize and deserialize the four-pane draft data including the new YARE type flag and JS code block.

### [MnesOS-260525-08] Frontend – "I'm feeling Lucky" Console UI
- **Status:** **Backlog**
- **Priority:** **Medium**
- **References:** `[MnesOS-260507-08]`
- **Objective:** Build a requirement entry and refinement console in the developer GUI where developers can generate and iteratively edit cartridges via plain-text specifications.
- **Description:**
    - Design and implement a dedicated sub-view or overlay "I'm Feeling Lucky" in the developer GUI.
    - Add a focused text input area for developers to describe cartridge requirements in plain English.
    - Keep the console accessible after initial generation, transitioning it to a "Refinement" mode that accepts feedback/modification prompts (e.g., "Make rules more lenient" or "Add a player partner").
    - Add a generation progress indicator showing the agentic pipeline's current step and active agent (e.g. "Drafting Lore...", "Compiling YARE...").

### [MnesOS-260525-09] Backend – "I'm feeling Lucky" Cartridge Generator Agent
- **Status:** **Backlog**
- **Priority:** **High**
- **References:** `[MnesOS-260507-09]`, `[MnesOS-260507-10]`, `[MnesOS-260525-07]`
- **Objective:** Implement the backend agentic AI orchestrator to generate and iteratively refine a complete four-file cartridge from a prompt, and persist the prompt alongside the cartridge metadata.
- **Description:**
    - Build a specialized agentic workflow that processes a requirement document or refinement feedback.
    - **Iterative Updates (Diffing)**: The endpoint must accept the user's latest prompt alongside the *current content of the 4 panes*, executing targeted code diffs/edits instead of starting from scratch.
    - Use the Architect and Specialist agent system to coordinate generation across the narrative files (`bot_lore.md`, `first_message.md`), configurations (`prompt_directives.yaml`), and logic (`yare.yaml`/`yare.js`).
    - Run the auto-validator tool on the generated/edited code and perform auto-correction loops for any compilation errors.
    - **Prompt Persistence**: Store the developer's raw prompt inside the database (e.g. in a new `generation_prompt` column of `cartridge_versions` table) for future schema updates, documentation, and version tracking.
    - Return the validated, complete cartridge files to the frontend console.

### [MnesOS-260525-10] Frontend – "Articulation Scramble" Speaking Mini-game
- **Status:** **Backlog**
- **Priority:** **Medium**
- **References:** `docs/design/mini-games.md`
- **Objective:** Implement a word-ordering persuasion/spell-casting game for resolving social checks, dialogue challenges, or spell articulation.
- **Description:**
    - Build a React mini-game component where players must construct a coherent sentence response by selecting words in the correct sequence.
    - Render a randomized grid of word buttons containing a superset of the correct sequence and the confusion words.
    - Support an optional `max_time_seconds` countdown timer. If set, the game automatically locks and submits when time expires; if omitted, the player manually commits their selection via an "End Response" button.
    - **Win/Lose Check:** The player wins if they select exactly the correct words in the correct sequence (and no more). Otherwise, they lose.
    - Register the component in `web-client/src/components/minigames/registry.ts` under the key `articulation_scramble`.
    - Define and export the game schemas:
        - **Difficulty:** `{ prompt: string, prefix: string, correct_sequence: string[], confuse_words: string[], max_time_seconds?: number }`
        - **Metrics:** `{ success: boolean, selected_sequence: string[], time_spent_seconds: number }`

### [MnesOS-260525-11] Frontend – "Reflex Dial" Action Mini-game
- **Status:** **Backlog**
- **Priority:** **Medium**
- **References:** `docs/design/mini-games.md`
- **Objective:** Implement a reflex-based QTE game representing physical combat, stealth evasion, or lock-picking.
- **Description:**
    - Build a React mini-game component where a needle rotates on a dial, and players must click/tap (or press specific keys) when the needle lands on highlighted success zones.
    - Support multiple cycles with moving and shrinking success zones.
    - **Key Sequences:** Support an optional `key_sequence` parameter. If provided, the game requires the player to press specific keyboard keys (e.g., arrow keys or WASD) when hitting the zones, displaying a visual heads-up overlay indicating the current and next key in the sequence.
    - Register the component in `web-client/src/components/minigames/registry.ts` under the key `reflex_dial`.
    - Define and export the game schemas:
        - **Difficulty:** `{ indicator_speed: number, zone_width_degrees: number, required_success_hits: number, key_sequence?: string[] }`
        - **Metrics:** `{ success: boolean, hits: number, misses: number, avg_reaction_time_ms: number }`

# MnesOS Implementation Plan – 2026-05-07

This plan outlines the Foundation and Gameplay tracks for parallel development. Tasks are structured as JIRA-style cards to enable clear ownership for 2-3 engineers.

---

## Phase 1: Foundation (CI/CD)

### [MnesOS-260507-01] CI – Implement Path-Filtering & Gatekeeper Pattern
- **Status:** **Done**
- **Objective:** Prevent PR blocking when specific sub-systems (Python or Web) are skipped.
- **Description:** 
    - Implement a `paths-filter` job to detect changes in `src/` vs `web-client/`.
    - Create a `ci-success` gatekeeper job that depends on all test workers.
    - Implement logic in `ci-success` to treat `skipped` results as `success`.
    - **Contract:** This will be the only required status check for branch protection.

### [MnesOS-260507-02] CI – Web-Client Unit Tests & Coverage Enforcement
- **Status:** **Done**
- **Objective:** Establish quality standards for the frontend.
- **Description:**
    - Configure Vitest/Jest in the `web-client` directory.
    - Update GitHub Actions to run frontend tests when `web-client/` changes.
    - Enforce a hard-fail threshold of 80% code coverage.

### [MnesOS-260507-03] CI – Full System E2E Integration Pipeline
- **Status:** **Done**
- **Objective:** Verify the unified application artifact.
- **Description:**
    - Update CI to build the web-client and mount the static output to the FastAPI backend.
    - Implement a Playwright test suite that boots the unified service.
    - Enforce E2E "Happy Path" verification (Auth -> New Game -> First Turn).

## Phase 2: Gameplay & Abstractions

### [MnesOS-260507-04] Auth – Implement Stateless Auth Abstraction Layer
- **Status:** **Done**
- **Objective:** Decouple the engine from specific auth providers.
- **Description:**
    - Define `AuthProvider` and `AuthValidator` abstract base classes.
    - Implement the `OpenRouterPKCE` strategy.
    - Refactor API middleware/dependencies to use an `AuthFactory` based on `X-Provider` headers.

### [MnesOS-260507-05] Engine – Implement LLM Provider Factory
- **Status:** **Done**
- **Objective:** Enable multi-model and multi-provider support.
- **Description:**
    - Define the `LLMProvider` interface (generate, embed).
    - Implement `OpenRouter` and `Gemini` concrete strategies.
    - Update LangGraph nodes to receive an injected `LLMProvider` rather than calling specific APIs.

### [MnesOS-260507-06] Engine – Hierarchical Config & RunnableConfig Mapping
- **Status:** **Done**
- **Objective:** Grant players and developers control over LLM parameters.
- **Description:**
    - Implement the `MnesOSRuntimeConfig` schema.
    - Create a `ConfigMerger` to combine Cartridge defaults, Player settings, and Request-level overrides.
    - Update the `Orchestrator` to map the merged config into the LangGraph `RunnableConfig["configurable"]` dictionary.

### [MnesOS-260507-07] Gameplay – Director Batch RAG Tool
- **Status:** **Done**
- **Objective:** Optimize cost and performance of lore retrieval.
- **Description:**
    - Implement the `multi_lore_lookup(queries: List[str])` tool.
    - Update the Director node’s system prompt to mandate batching of information lookups.
    - Refactor the graph to make RAG an active tool call instead of a pre-node injection.

## Phase 3: Cartridge Developer Features

### [MnesOS-260507-08] Builder UI – IDE-lite Split-Pane Layout
- **Status:** **Backlog**
- **Objective:** Provide a high-productivity authoring environment.
- **Description:**
    - Implement the split-pane layout: Chat Agent (Left) and 4-Tab Live Preview (Right).
    - **Tabs:** World Lore (`.md`), Game Rules (`.yaml`), AI Directives (`.yaml`), and Intro Message (`.md`).
    - **Bi-directional Sync:** Ensure manual edits in the preview pane are reflected back into the Agent's context.

### [MnesOS-260507-09] Builder Backend – Architect & Specialist Multi-Agent System
- **Status:** **Backlog**
- **Objective:** Ensure high-quality generation across narrative and technical domains.
- **Description:**
    - Implement a LangGraph orchestrator (Architect) that delegates to specialized workers.
    - **Lore Master Node:** Handles markdown worldbuilding and consistency.
    - **Mechanic Node (YARE Expert):** Handles English-to-YAML translation.
    - **Prompter Node:** Handles role steering and intro narrative.
    - **Contract:** The Mechanic node MUST include rich YAML comments for every generated state/event.

### [MnesOS-260507-10] Builder Tools – YARE Translator & Auto-Validator
- **Status:** **Backlog**
- **Objective:** Enable deterministic logic generation with auto-correction.
- **Description:**
    - Build the `yare_translate` tool: English -> (YAML Block + Logic Explanation).
    - Build the `cartridge_validate` tool: Wraps the existing `CartridgeLoader` to provide agents with immediate feedback for auto-correction loops.

### [MnesOS-260507-11] Builder Persistence – Versioned Drafts & ZIP Export
- **Status:** **Backlog**
- **Objective:** Ensure user work is safe and portable.
- **Description:**
    - Implement the `cartridge_drafts` table with **Auto-save** and **Version History** (Retention: k=3).
    - Implement a one-click **ZIP Export** feature that packages the 4 draft files into a standard MnesOS cartridge structure.

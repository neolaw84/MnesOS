# MnesOS Implementation Plan – 2026-05-10

This plan outlines the engine distribution strategy, infrastructure setup, and the multi-layered guardrail architecture for MnesOS. Tasks are structured as JIRA-style cards to enable clear ownership.

---

## Phase 1: Engine Distribution & Model Management

### [MnesOS-260510-01] UI – In-Engine Model Manager
- **Status:** **Backlog**
- **Objective:** Provide users with a native interface to manage local models.
- **Description:** 
    - Build a "Model Manager" UI component for the desktop client.
    - Enable viewing of downloaded models, available disk space, and VRAM requirements.

### [MnesOS-260510-02] Distribution – Implement Downloader Pattern
- **Status:** **Backlog**
- **Objective:** Mitigate legal liability and reduce repository size.
- **Description:**
    - Configure the engine to fetch Hugging Face weights at runtime.
    - Implement a progress tracker for downloads within the UI.
    - Ensure models are stored outside of the core application directory.

### [MnesOS-260510-03] Legal – License Click-Throughs & AUP Transfer
- **Status:** **Backlog**
- **Objective:** Ensure compliance with model-specific Acceptable Use Policies.
- **Description:**
    - Add explicit license acceptance dialogs for users downloading Llama-based or restricted models.
    - Log local acceptance to satisfy "Downloader Pattern" liability transfer requirements.

### [MnesOS-260510-04] Auth – BYOK Flow for SaaS Tier
- **Status:** **Done**
- **Objective:** Enable user-funded API usage for the hosted service.
- **Description:**
    - Integrate a "Bring Your Own Key" (BYOK) authentication flow in the UI.
    - Support entry and validation of OpenRouter or provider-specific API keys.

## Phase 2: API & Infrastructure Setup

### [MnesOS-260510-05] Infra – OpenRouter Premium Routing
- **Status:** **Backlog**
- **Objective:** Establish reliable routing for high-performance cloud models.
- **Description:**
    - Establish API routing for **hosted** "premium" models via OpenRouter or direct IaaS providers (RunPod/Together).
    - Implement cross-provider fallback logic to maintain service continuity for cloud-hosted sessions if the primary aggregator fails.

### [MnesOS-260510-06] Infra – Regional Geo-Blocking (Australia)
- **Status:** **Backlog**
- **Objective:** Mitigate immediate regulatory risks in restrictive jurisdictions.
- **Description:**
    - Implement IP-based geo-fencing to block traffic from Australia for the hosted service.
    - Add clear error messaging for blocked regions explaining the regulatory context.

### [MnesOS-260510-07] Infra – Local Model Tier Configuration
- **Status:** **Backlog**
- **Objective:** Define the target model set for local hardware tiers.
- **Description:**
    - Define model presets (e.g., Qwen, Llama variants) optimized for local hardware tiers: Tiny (<4GB VRAM), Small (6-8GB), and Midsize (12-16GB).
    - Tune system prompts specifically for local execution constraints to ensure reliable tool-calling on lower-parameter local models.

## Phase 3: Guardrail Implementation (Strategy Pattern)

### [MnesOS-260510-08] Architecture – Abstract GuardrailStrategy Interface
- **Status:** **Backlog**
- **Objective:** Enable hot-swappable safety levels.
- **Description:**
    - Define `GuardrailStrategy` in Python with `validate_input()`, `validate_output()`, and `validate_json_structure()` methods.
    - Implement the base abstraction in `src/MnesOS/guardrails/base.py`.

### [MnesOS-260510-09] Logic – SFW and NSFW Concrete Strategies
- **Status:** **Backlog**
- **Objective:** Support both narrative freedom and strict safety.
- **Description:**
    - Create `StrictSFWStrategy` for general-purpose play.
    - Create `UncensoredRPStrategy` for mature/private contexts.
    - Integrate content classification checks specific to each strategy.

### [MnesOS-260510-10] Engine – Strategy Injection into Graph
- **Status:** **Backlog**
- **Objective:** Dynamically apply guardrails based on request context.
- **Description:**
    - Update `src/MnesOS/graph/factory.py` to extract the active strategy from `RunnableConfig`.
    - Refactor `director.py` to use the injected strategy for validation.

## Phase 4: MnesOS Graph & API Updates

### [MnesOS-260510-11] Security – Static Cartridge Defense
- **Status:** **Backlog**
- **Objective:** Prevent malicious or broken cartridges from entering the system.
- **Description:**
    - Update `create_cartridge_version` in `src/MnesOS/api/cartridges.py`.
    - Run content classification on `bot_lore.md`, `yare.yaml`, and `prompt_directives.yaml` before database insertion.

### [MnesOS-260510-12] Graph – Input Node Prompt Guard
- **Status:** **Backlog**
- **Objective:** Scrub player intent before processing.
- **Description:**
    - Integrate Prompt Guard immediately after `reset_agent_messages_node`.
    - Intercept and handle malicious injection attempts or protocol violations.

### [MnesOS-260510-13] Graph – Director Node Schema Enforcement
- **Status:** **Backlog**
- **Objective:** Guarantee deterministic output for game logic.
- **Description:**
    - Wrap the `director_node` tool invocation with Guardrails AI (Python).
    - Strictly enforce JSON schemas for YARE events to prevent engine crashes.

### [MnesOS-260510-14] Graph – Output Node Llama Guard
- **Status:** **Backlog**
- **Objective:** Evaluate final rendered prose for safety compliance.
- **Description:**
    - Create `output_guardrail_node` using Llama Guard 3.
    - Position node between `narrator_node` and `cleanup_agent_messages_node`.
    - Render a "Content Blocked" message if the output violates the active strategy.

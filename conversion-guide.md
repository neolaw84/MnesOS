# Agentic RPG Engine: Cartridge Development & Conversion Guide

This guide is intended for developers converting traditional string-based or Markdown-scripted roleplaying bots (such as vanilla Janitor AI cards) into **Cartridges** for the Agentic RPG Engine.

## 1. Engine Philosophy

In a typical LLM-driven bot, the Language Model handles everything: narration, tracking stats, calculating exhaustion drops, and tracking mechanics. Because LLMs are inherently stochastic (random), they fail at math, forget trackers, or randomly allow players to break the game rules.

The Agentic RPG Engine uses a LangGraph-powered **ReAct Workflow** combining multiple LLMs with a sandboxed Python runtime to completely decouple math from creativity:
1. **The Director Node (LLM):** Parses what the player wants to do and triggers deterministic rules.
2. **The Rules Engine (Python):** Automatically calculates math, modifies states enforce limits, and rolls dice using the **YARE** specification.
3. **The Context Node (RAG):** Automatically finds the most relevant world-building "Lore" based on the ongoing scene.
4. **The Narrator Node (LLM):** Takes the absolute truths generated by the Rules Engine and the Context Node, and beautifully writes the scene prose with 0% mathematical hallucination.

To make a game work in this engine, you must abstract the bot into a **Cartridge**.

---

## 2. Cartridge Structure

A Cartridge defines a unique game setting. It must be created inside `sandbox/cartridges/<your-game-name>/` and requires exactly two files:

1. `bot_lore.md`: The world-building and narrative context.
2. `yare.yaml`: The strict mechanical rules and database schema.

---

## 3. Formatting `bot_lore.md` (Vector RAG)

The engine does not pass your entire character sheet to the LLM on every turn (this saves money and prevents prompt bloat). Instead, it uses Vector Similarity Search to inject only the relevant paragraphs.

**Formatting Rules:**
- The engine segments the file based on **Markdown Headers** (`#`, `##`, `###`).
- Write descriptive headers. If a section is about "The Underground Arena", put everything regarding it under `## The Underground Arena`.
- Do NOT put game mechanics (like "If player rolls 3d6") in this file. This file is pure creative prose.

**Example `bot_lore.md`:**
```markdown
# Neon District
The neon district is a seedy underbelly fueled by corruption and underground cyborg modifications. 

# The Jackhammer (NPC)
The Jackhammer is a brutal, towering figure with no mercy. He prefers close-quarter grapples.
```

## 4. Writing `yare.yaml` (YAML Agentic Rules Engine)

The YARE file acts as the executable code for your game. Because it is a YAML file executing on a Directed Acyclic Graph (DAG) parser, it is 100% immune to infinite loops, making it secure for servers.

### 4.1 Schema Definition
You must definitively type every variable your game tracks. The engine natively restricts values to their bounds.

```yaml
version: "1.0"
bot_name: "my-game"

state_schema:
  player:
    stamina: { type: int, default: 100, min: 0, max: 100 }
    is_poisoned: { type: bool, default: false }
  npc:
    dominance: { type: int, default: 10 }
```

### 4.2 Macros
Define reusable mathematical chunks. Use the `@` prefix to signify the expression sub-language.
```yaml
macros:
  power_bonus: "@ (state.player.stamina >= 80) * 3 + (state.player.stamina < 30) * -1"
```

### 4.3 Events (The Verbs)
Events are what the "Director LLM" is allowed to call when mapping user action. Every bot should have mechanical triggers and at least one generic fallback trigger.

Events contain an array of `steps`. The allowed Actions are:
*   `set`: Assign explicitly.
*   `mutate`: Mutate against numbers natively.
*   `branch`: Evaluate conditional `if / else` rules.
*   `table_roll`: Map a single roll/expression into string outputs (ideal for NPC archetype setups).
*   `call`: Run a separate block of events as a macro.
*   `note`: An absolutely critical field. This outputs the string result back to the Narrator LLM.

#### Example Event: Resolving Combat
```yaml
events:
  # Triggered when player says "I attack him!"
  attack:
    steps:
      - action: set
        var: temp.player_score
        value: "@ roll(3d6) + macros.power_bonus"
        
      - action: branch
        conditions:
          - if: "@ temp.player_score >= 12"
            steps:
              - action: mutate
                var: state.npc.dominance
                op: sub
                value: 5
              - action: note
                message: "Player scored {temp.player_score}. Attack succeeded. NPC dominance dropped."
                
          - else:
            steps:
              - action: mutate
                var: state.player.stamina
                op: sub
                value: 15
              - action: note
                message: "Player missed. Counter attacked. Stamina dropped 15."

  # Triggered when player says "I try to pick the lock"
  generic_check:
    inputs: [stat, difficulty]
    steps:
      - action: branch
        conditions:
          - if: "@ roll(3d6) >= inputs.difficulty"
            steps:
              - action: note
                message: "Generic Action Succeeded."
          - else:
            steps:
              - action: note
                message: "Generic Action Failed."
```

## 5. Converting Legacy JavaScript/Markdown Bots

Many existing Janitor AI cards attempt to force math using markdown blocks `<PRE_COMPUTED_DATA>` alongside regex-parsing via JS evaluators. 

**Steps to Convert:**
1.  **Extract the Rules**: Look at the original `scenario.md` and read the Javascript payload. Rip out the math (e.g. `roll(4d5)`) and reconstruct it as `steps` inside `yare.yaml`.
2.  **Define Bounds**: If the legacy rule states "Stamina never goes below 0", simply add `min: 0` to your `state_schema`. The engine will now handle it.
3.  **Remove Regex Displays**: Older bots force UI printing via markdown tables (`[Stamina: X]`). You do NOT need to write this logic. In the Agentic Engine, the `Narrator Node` is natively programmed to append the state variables to the bottom of the output perfectly every time.
4.  **Extract Context**: Remove the City Descriptions, NPC appearances, and items from the bot config, dump them into `bot_lore.md`, and format them with Markdown Headers.

---

## 6. Testing

Once your `yare.yaml` and `bot_lore.md` are added to a folder inside `/cartridges/`, simply load the engine graph pointing to that directory. The LangGraph routing, AST Interpreter, and Vector Searches will handle everything else.
